# Mien: identity, first use and everyday interaction

This implementation supersedes the lime/glass visual iteration. The canonical logo is retained: two asymmetric warm-white and steel planes, a graphite field, and a small ultramarine inflection. Those existing assets provide a coherent identity for the actual native product.

The product expression is **在当前窗口，直接提问。** The source window and the answer carry the experience. Account setup, model selection and permissions have explicit places; they do not compete with everyday reading. This is implemented product work, not a claim of user acceptance or a completed consumer release.

## Decisions

| Area | Implemented behavior |
|---|---|
| Identity | One palette owner, warm light/graphite dark reading surfaces, ultramarine primary actions, and a small monochrome derivative of the canonical mark. |
| First use | One required next step in a 480 × 340 pt native window; exact browser code during authorization; one granted reading capability is sufficient. |
| Settings | A separate 520 × 400 pt native window for account, server-discovered model choice, permissions and shortcut guidance; Command–Comma works from the conversation. |
| Conversation | 520 pt width, 20 pt margins, 13 pt secondary question, 15 pt answer/input, fine outlined composition surface, bounded native scrolling. |
| Actions | Visible copy and process disclosure; explicit insertion/undo; acknowledgements use native accessibility notifications. |
| Entry and recovery | Standard menu-bar menu on ordinary click, truthful setup/current-task/continue labels, native App/Edit/Window commands, typed target-failure feedback. |
| Language | The account is ChatGPT throughout connection and recovery; task progress and errors use ordinary product language. Provider/runtime names remain appropriate in account/model choices and diagnostics. |

The narrower surface shows less text per line than the earlier 600 pt panel. Smaller question typography and compact chrome return emphasis and vertical room to the answer. Stable opaque reading surfaces avoid nested compositing and appearance mismatches. These are deliberate design tradeoffs, not evidence that all users prefer this layout.

## Responsible boundaries corrected

- Setup and Settings previously shared one large controller and welcome layout. `MienReadinessController` now owns lifecycle and live facts; separate setup/settings view controllers project them through a small `ReadinessActions` interface. No introduction flag becomes permission truth.
- First use previously asked for optional Screen Recording after Accessibility was already authorized. The shared next-action policy now finishes when live connection, model availability and one reading route establish usability. Exact Agent-requested capabilities still require authorization at the Host boundary.
- An unchanged model catalog caused `AgentModelPicker.apply` to skip rebuilding, while Settings could leave the control disabled after reconnection. Settings now derives enabled state from current connection/catalog facts independently of rebuilding the menu. A regression covers connected → connecting → connected with the same catalog.
- Clearing a detached-task status previously made a retained conversation's menu label resemble a new invocation. Menu labels now consult conversation existence independently of the attention badge.
- Missing target identity previously produced a beep with no useful route forward. Typed invocation errors now project into an accessible native popover, with a content-free log; target authority is never guessed or widened.
- The initial compact panel height omitted input-container padding. Shared geometry now includes it before the first resize.
- Native inspection reproduced Command–W doing nothing in the setup window. A native Window menu provides the standard close command. The nonactivating panel routes both that action and Command–W through its existing cancellation/cleanup boundary; it never closes an untracked task window directly.
- The permission guide now distinguishes adding Mien to Apple's list from granting access. Its preview honors the requested light/dark appearance and fails explicitly if the canonical icon is missing.

## Engineering retained

Conversation data remains separate from disposable native table cells. Offscreen cells release WebKit resources, reconstruct exact Markdown and disclosure state when revisited, and reject obsolete height callbacks. The composer stays pinned outside history scrolling. Completed Pi turns discard raw captured payloads while retaining dialogue and typed receipts.

Startup recovery and executable integrity checks remain in `MienRuntimeBootstrap`, away from MainActor. `MienApplicationController` owns application wiring; `MienConversationController` and `ConversationWorkQueue` own task binding and awaited cleanup. The Host still passes verbatim input to one conversation-bound Agent, accepts only typed decisions/outcomes, and never infers intent from copy or appearance.

No runtime protocol, prompt, tool negotiation, credential destination or packaging policy changed in this rebrand. The existing live Pi evidence is documented in the preceding lifecycle reports; it is not represented as a new live model-turn test here.

## Evidence and limits

Evidence is local under `.build/rebrand-pass/`:

- `verify.log`: complete `scripts/verify-mien.sh` run, including 193 passed Swift tests (5 opt-in tests skipped), 13 Pi tests, 4 renderer tests, release build, strict formatting, resource checks and native fixture generation. No conflicting-constraint warnings were emitted.
- `after/` and `after-dark/`: 13 actual AppKit-rendered fixtures per appearance, including all six setup/settings states and the permission guide. Conversation text, authorization codes and model names in these images are fixtures, not live replies or account state.
- `resources.log`: the 24-turn rendered workload retained **2 WebViews and 96 descendant NSViews**; the 60-turn release/revisit/reset regression passed. Counts establish a structural resource boundary, not RSS, energy use or unlimited-history acceptance.
- The same local probe measured startup preparation at **93.3 ms** with **6.3 ms maximum MainActor heartbeat gap**; synchronous executable verification occupied **99.5 ms** at the old boundary. This single local sample used the previously installed identical runtime helpers, warm filesystem caches and concurrent preview rendering. It is not a clean-machine cold-start or percentile benchmark.
- `install.log` records canonical universal assembly, exact-process installation and nested signature verification through `script/build_and_run.sh --verify`. The final installed Host process was PID 95255.

Native inspection confirmed the account connected, the preserved GPT-6.1-Sol preference, and a live server menu containing GPT-6/6.1 families. Command–Comma opened Settings; Escape dismissed its model menu; returning to setup preserved the live permission state. The final installed Window menu exposes native `performClose:` and the panel cleanup regression passes. After Command–W, the UI tool could no longer read a window and timed out; the same application responded to Command–Comma and presented Settings again. The Window menu required its exposed AX Cancel action to dismiss during automation, so its Escape behavior is not counted as passed. Neither capture permission was granted during inspection.

Real target acquisition, draft insertion and undo under granted TCC, full VoiceOver navigation, accessibility-display combinations, older supported macOS versions, cold-start percentiles and long-running energy/soak measurements remain acceptance boundaries. The locally installed build is ad-hoc signed, not a notarized consumer release. Visual acceptance by the user is not assumed.

## Platform guidance

Apple's [onboarding guidance](https://developer.apple.com/design/human-interface-guidelines/onboarding) recommends postponing nonessential setup and teaching the current task. Its [Settings guidance](https://developer.apple.com/design/human-interface-guidelines/settings) supports useful defaults, compact configuration, and the standard macOS Settings command. These informed the separation of first use from ongoing configuration.

Modern Web Guidance's `typography` guide says: “Use unitless numbers for `line-height`”. The offline document uses 1.6 line height, host-projected `rem` sizing, paragraph-only pretty wrapping and heading-only balancing. Native AppKit still owns input, state, controls, and accessibility actions.
